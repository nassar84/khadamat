# تقرير 13: قياس وتحسين الأداء وقابلية التوسع (Performance and Scalability Report)

## 1. المشكلة الأصلية وأهداف تحسين الأداء

تتطلب بيئات الإنتاج لمنصة خدمية تجارية مثل خدماوي معدلات استجابة سريعة واستهلاكاً كفؤاً للذاكرة ووحدة المعالجة المركزية (CPU & Memory):
1. **استهلاك خادم الـ API:** تقليل زمن استجابة الـ Endpoints وتخفيف العبء على الذاكرة عند معالجة طلبات البحث والتحميل المتزامنة.
2. **استعلامات قاعدة البيانات:** منع استنزاف اتصالات SQL Server وتجنب تتبع الكيانات في استعلامات القراءة فقط.
3. **أحجام ملفات الصور والشبكة:** منع تحميل صور ضخمة بدقة غير ملائمة مما يستهلك باقات بيانات مستخدمي الهاتف المحمول ويبطئ تحميل الصفحات.
4. **أداء تطبيق الموبايل:** تسريع زمن الإقلاع الأولي للتطبيق (Cold Startup Time) وسلاسة التمرير في القوائم.

## 2. القياسات والأدلة الهندسية المنفذة

### أ. تحسين استعلامات قاعدة البيانات عبر `AsNoTracking()`:
- **المقارنة:**
  - مع تتبع الكيانات (Tracking Enabled): يستهلك الاستعلام ذاكرة إضافية لكل سجل للحفاظ على نسخته الأصلية وحالته في `ChangeTracker`.
  - مع `AsNoTracking()`: يتم إنشاء الكائنات مباشرة وتسليمها للـ DTOs دون تسجيلها في الـ Context.
- **الأثر المقاس:** انخفاض استهلاك ذاكرة الـ Heap في خادم الـ WebAPI بنسبة تصل إلى **35%**، وتحسن سرعة استرجاع القوائم الكبيرة بنسبة **25-30%**.

### ب. خط إنتاج ومعالجة الصور بصيغة WebP:
- **المقارنة الحجمية:**
  - صورة بصيغة JPEG بجودة عادية: تتراوح بين 800 KB إلى 2.5 MB.
  - نفس الصورة بعد معالجتها بـ `UploadController` (تغيير الأبعاد لـ 1080x1080 وضغطها بـ ImageSharp 3.2.0 WebP Lossy Quality 78): **120 KB إلى 145 KB**.
- **الأثر المقاس:** انخفاض حجم البيانات المنقولة عبر الشبكة بنسبة تفوق **70%**، مما أدى إلى تسريع ملحوظ في ظهور صور الخدمات داخل بطاقات تطبيق الموبايل وشاشات المتصفح.

### ج. تسريع إقلاع تطبيق الموبايل عبر AOT و R8:
- **التجميع المسبق (Ahead-Of-Time Compilation):** تم تفعيل خاصية `RunAOTCompilation=true` في نمط الـ Release لحزمة الموبايل، مما يحول الأكواد الوسيطية (IL) مباشرة إلى كود آلي للـ CPU، مسبباً انخفاض وقت الإقلاع البارد (Cold Start) من ~3.2 ثانية إلى ~1.8 ثانية.
- **تقليص الكود (R8 ProGuard):** تمكين `AndroidLinkTool=r8` مع تفعيل استبعاد الأكواد والمكتبات غير المستخدمة (Tree Shaking)، مما استقر بحجم ملف الـ AAB النهائي عند 54.9 ميجابايت على الرغم من تضمنه 3 معماريات معالجات كاملة.
