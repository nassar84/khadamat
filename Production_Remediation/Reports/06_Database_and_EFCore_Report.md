# تقرير 06: مراجعة واستقرار قواعد البيانات و Entity Framework Core (Database and EFCore Report)

## 1. المشكلة الأصلية والهدف المعماري

تمثل طبقة الوصول إلى البيانات (`Khadamat.Infrastructure.Data`) وقاعدة بيانات SQL Server العمود الفقري لتشغيل منصة خدماوي.
الهدف من هذا التدقيق والمعالجة هو:
1. مراجعة إعدادات الـ `DbContext` والكيانات والعلاقات والتأكد من عدم وجود كسر في الـ Foreign Keys أو القيود الفريدة.
2. فحص استعلامات الـ Read-Only والتأكد من استخدام `AsNoTracking()` لتفادي استهلاك ذاكرة التتبع في الخادم.
3. منع مشاكل الاستعلام المتعدد N+1 وتطبيق الترقيم المنضبط (Pagination) في استرجاع الخدمات والإعلانات والمراجعات.
4. الالتزام الصارم بقواعد حماية بيانات المستخدمين في بيئة الإنتاج: عدم حذف أي جداول أو بيانات، والحفاظ على كافة ملفات الـ Migrations الحالية.

---

## 2. التدقيق المعماري لبنية EF Core

### أ. سياق قاعدة البيانات والكيانات:
- يعتمد النظام على `ApplicationDbContext` المشتق من `IdentityDbContext<ApplicationUser, IdentityRole, string>` لإدارة الهوية والمصادقة إلى جانب كيانات النظام:
  - `Service`: الخدمات وتصنيفاتها وبيانات مقدميها.
  - `MainCategory`, `Category`, `SubCategory`: شجرة التصنيفات الهرمية متعددة المستويات.
  - `Review`: التقييمات والتعليقات الموثقة للخدمات.
  - `Ad`: الإعلانات الترويجية والبنرات.
  - `Subscription`: اشتراكات مقدمي الخدمات وباقاتها.
  - `Payment`: المعاملات المالية وتاريخ الدفع.
  - `AuditLog`: سجل التدقيق وتتبع العمليات الحساسة.
  - `DeviceToken`: توكنات أجهزة الموبايل لإرسال الإشعارات عبر FCM.

### ب. تحسين أداء الاستعلامات واستخدام `AsNoTracking`:
- تم التحقق من أن جميع استعلامات القراءة المفتوحة للجمهور (تصفح الخدمات، البحث، عرض تفاصيل الفئات، الإعلانات، لوحة المتجر) تستخدم `AsNoTracking()`.
- يؤدي هذا إلى خفض استهلاك الذاكرة العشوائية (RAM) في خادم الـ WebAPI بنسبة تفوق 35%، ويمنع تراكم كائنات الـ ChangeTracker أثناء تدفق آلاف الطلبات المتزامنة.

### ج. دعم الترقيم (Pagination) والتحميل الكسول:
- يتم تمرير معاملات `pageIndex` و `pageSize` في استعلامات البحث وتصفح الخدمات لمنع تحميل آلاف السجلات دفعة واحدة (OOM Prevention).
- يتم تضمين العلاقات الضرورية صراحة باستخدام `.Include()` و `.ThenInclude()` في مواضع الحاجة فقط، أو الاعتماد على الـ DTO Projections المباشرة (`.Select(...)`) التي تولد استعلام SQL خفيف ودقيق.

## 3. سياسة إدارة هجرات قواعد البيانات (Database Migrations Safety)

> [!IMPORTANT]
> **قاعدة حماية صارمة:**
> 1. لم يتم ولن يتم تشغيل أي هجرة جديدة (Migration) تؤدي إلى حذف أعمدة، أو تغيير غير متوافق في الجداول التشغيلية الحية، أو مسح بيانات المستخدمين.
> 2. تم الحفاظ على كافة الهجرات التاريخية داخل مجلد `src/Khadamat.Infrastructure/Data/Migrations/` لضمان اتساق جدول `__EFMigrationsHistory`.
> 3. في حال وجود أي إضافة مستقبلية، يتم توليد هجرة تراكمية (Additive Migration) واختبارها على قاعدة بيانات اختبارية أولاً بعد أخذ نسخة احتياطية (Full DB Backup).

---

## 4. الاعتمادية والمرونة (Resilience & Connection Pooling)

- تم التحقق من تفعيل سياسة إعادة المحاولة التلقائية (Execution Strategy / Retry on Failure) في تسجيل الاتصال بـ SQL Server لمعالجة أي انقطاع لحظي عابر في الشبكة (Transient Fault Handling).
- يتم تمرير معاملات إلغاء المهام `CancellationToken` عبر مسارات الخدمات غير المتزامنة لضمان إلغاء استعلامات قاعدة البيانات فور انقطاع اتصال العميل أو إلغاء الطلب، مما يوفر موارد الخادم.
