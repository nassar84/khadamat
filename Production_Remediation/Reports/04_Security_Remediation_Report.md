# تقرير 04: المعالجة الأمنية الشاملة وحماية النظام (Security Remediation Report)

## 1. المشكلات الأمنية المستهدفة

شمل التدقيق الأمني لمنظومة خدماوي عدة محاور حساسة تتطلب معالجة حاسمة قبل الإطلاق الإنتاجي:
1. **تأمين ملفات الرفع والصور (`UploadController`):** الحماية من رفع ملفات خبيثة، التلاعب بالامتدادات، أو هجمات تخريب المسارات (Path Traversal)، واستهلاك موارد الخادم (DoS / Memory Exhaustion).
2. **أمان واجهات برمجة التطبيقات (API & Authorization Security):** حماية نقاط النهاية (Endpoints) وفرض سياسات الصلاحيات على الخادم لمنع أي مستخدم من الوصول لوظائف المشرفين أو بيانات المستخدمين الآخرين (IDOR).
3. **أمان توقيع ومصادقة جلسات المستخدمين (JWT Security):** تجنب إخراج المستخدمين عند تدوير المفاتيح أمنياً، ومنع قبول توكنات صادرة بمفاتيح ملغاة.
4. **عزل وتطهير الأسرار وبيانات الاعتماد:** منع تضمين المفاتيح الحساسة في الكود أو ملفات النشر العامة.

## 2. الإجراءات الأمنية المنفذة بالتفصيل

### أ. تعزيز أمان رفع الملفات والصور (`UploadController.cs`):
- **التحقق من الامتدادات المسموحة فقط:** قصر الأنواع المقبولة على قائمة بيضاء صارمة (`.jpg, .jpeg, .png, .webp, .gif`).
- **تحديد الحجم الأقصى الصارم:** فرض سقف 10 ميجابايت للملف مع تحديد أحجام مستهدفة نهائية بحسب النوع (مثلاً 150 كيلوبايت كحد أقصى لصور الخدمات).
- **منع استخدام أسماء ملفات المستخدم (Secure Random Naming):** توليد أسماء عشوائية بالكامل بصيغة `${DateTimeOffset.UtcNow.ToUnixTimeMilliseconds()}_{Guid.NewGuid():N}.webp`، مما يمنع نهائياً أي محاولة لتسمية ملفات تنفيذية أو تداخل الأسماء.
- **الفحص الفعلي لترويسة ومحتوى الصورة (Safe Header & Image Decoding):** استخدام دالة `Image.LoadAsync<Rgba32>(inputStream)`؛ حيث تقوم مكتبة ImageSharp بقراءة وفك ضغط هيكل الصورة الداخلي (Magic Bytes)، وفي حال كان الملف تنفيذي أو نصي أو تالفاً يتم رفضه فوراً قبل حفظه.
- **الحماية الصارمة من هجمات Path Traversal في الحذف والإدارة:**
  ```csharp
  if (filename.Contains("..") || filename.Contains("/") || filename.Contains("\\"))
      return BadRequest(new { success = false, message = "اسم الملف غير صحيح" });
  ```
- **حماية عمليات الحذف ورفع بنرات Hero بصلاحيات المشرف فقط:**
  تطبيق وسم `[Authorize(Policy = "RequireAdmin")]` لمنع أي مستخدم عادي من التعديل على البنرات أو حذف الصور.

### ب. تعزيز نظام مصادقة وتدوير مفاتيح JWT:
- تطبيق واجهة ونظام `IJwtKeyManager` في [`src/Khadamat.Infrastructure/Identity/JwtKeyManager.cs`](file:///d:/DEV/khadamat/src/Khadamat.Infrastructure/Identity/JwtKeyManager.cs).
- إضافة معرّف المفتاح `kid` في ترويسة التوكنات الجديدة.
- دعم مفاتيح متعددة متزامنة مع فترة سماح (`grace_period`) تتيح قبول التوكنات القديمة الصالحة لحين انتهائها، مما يحقق **Zero-Downtime Rotation**.
- الرفض الفوري للتوكنات الموقعة بمفاتيح معطلة أو مسحوبة (`retired`).
- توفير آلية التوافق العكسي (Fallback) للتوكنات التاريخية التي لا تحتوي على `kid`.

### ج. أمان الخادم والصلاحيات (Server-Side Authorization):
- **التحقق في طبقة الخادم:** التأكد من أن جميع وحدات التحكم والعمليات الحساسة (إدارة المستخدمين، تفعيل مقدمي الخدمات، حذف البيانات، التقارير المالية) مفروضة بوسم `[Authorize(Roles = "Admin")]` أو `[Authorize(Policy = "RequireAdmin")]`.
- **منع تسريب البيانات الحساسة:** تنقيح استجابات الـ DTOs لعدم إرجاع تجزئات كلمات المرور أو أسرار المصادقة الثنائية.
